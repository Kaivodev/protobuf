# Kaivo contract repository rules

- Maintain all inter-service `.proto` files only in this repository. The backend service maintains the HTTP/EPay Swagger documentation separately from the gRPC interfaces.
- Use Redis + Asynq for asynchronous tasks only within a single trust domain. This repository maintains versioned Protobuf payloads for cross-service tasks within that domain. The owning service maintains the task handlers. Across trust domains, use only mTLS gRPC contracts. The sender's outbox relay can call the receiver, or the receiver can pull signed events. The receiver processes events idempotently by event ID. Do not define cross-domain Asynq task payloads. See `architecture/security.md` in the docs repository for trust domain boundaries and `design/contracts.md` for contract design. Add a protocol only when it has a concrete use case.
- Every RPC must use the method option `(aipay.authz.v1.policy)` to declare allowed callers, identity assertion requirements (no assertion, required assertion, required assertion with MFA and recent authentication, or single use) and acceptable permissions. Use the values from the synchronous RPC list in `design/contracts.md` in the docs repository. `make check` rejects methods without a policy.
- Use versioned package names such as `aipay.<service>.v1`. Set `go_package` to the corresponding path under `gen/go` in this repository.
- Implement RPCs, signed events and payloads for payment, ledger, settlement and reconciliation according to `design/contracts.md` in the docs repository and each service's detailed design. Follow the roadmap starting at M0. Update the design before adding any field, event or RPC it does not cover.
- IAM must be able to verify identities, organization membership and the source of permissions. IDs, scopes and trace fields in a request cannot establish authorization on their own. Reject requests on unknown enum values, missing constraints, expired assertions or service errors.
- Never log credentials, tokens or authentication assertions. Keep real keys out of protocol comments, examples and tests.
- The Makefile pins the code generation tool versions. Run `make fmt`, `make generate` and `make check`. Generated code must match its source.
- Never edit generated code by hand or reuse published field numbers. Use `reserved` for deleted fields. For breaking changes, use a new versioned package and run the Buf breaking check.
- Follow Conventional Commits. Include the background, decisions, verification and follow-up work in the commit body so collaborators and other AI agents can continue the work.
- Commit or push only when asked. Preserve the existing remote configuration. CLAUDE.md must reference only this file.
